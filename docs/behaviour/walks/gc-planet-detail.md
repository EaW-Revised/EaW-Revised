## Tray landing (project rule for GPD-22 and GPD-23)

The land tray is a drag source. Pressing an enabled tray slot, moving, and releasing over a unit pad lands that type's first disclosed orbiting unit on the pad and remembers the pad's marker for it. If the pad already holds a unit, that unit is launched to orbit first (GPD-23, first orbit position). A release anywhere else just ends the drag.

**Gesture confirmed by the original capture (legacy EAWR-5725).** Press, drag and release on a free unit pad lands the unit while the game runs; while paused the drop is refused (GPD-37). Landing on an occupied pad was not captured, so the launch-then-land order stays a project rule.

**One drop, three commands.** The viewer submits the launch (when the pad is occupied), the landing and the marker as three ordinary seat commands in one command boundary, in that order, through the normal player-command path (so co-op peers apply them identically). Before submitting anything it checks every admission the three commands make against the published state: pause policy for a deploy and for a layout change, ownership, the unit being a local landable transport in orbit at the planet, the occupant being launchable, surface capacity counted after the launch, and the marker being free once the occupant's entry is gone. If any check fails nothing is submitted, the player hears the refusal cue, and the match carries on. The simulation still re-checks each command when it runs; a state change between the check and the execution tick can refuse the later commands, which leaves the occupant in orbit with no landing.
