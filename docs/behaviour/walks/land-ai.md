# Walk 26: land tactical AI

## Scope, sources and evaluation boundaries

This walk covers the computer player's land battle: map-zone and object perception,
goal selection, company and hero grouping, attack/defence/capture plans, free units,
garrisons, pad construction, support attacks and reinforcement landing. Land skirmish
is the proposed test bed; campaign land battles also supply a parent-mode roster and
credit account. Combat resolution belongs to [land combat](land-combat.md), movement
to the land pathing walk, and the shared goal/plan engine to
[tactical AI](tactical-ai.md) and [the engine note](../foc-tactical-ai.md).

Comparison base: `cf94df0ba2928b80ce2b230e08a5dfdbd3fff97e`. The current tactical host
loads space plans and reports space mode. A missing land integration is not a
measured defect in a running land opponent. **Same** below means an existing shared
contract, with the stated land boundary; it does not certify an installed land game.
No retail recording was made, and no game code or tag statuses change in this walk.

Evidence is **debug build**, **effective XML/Lua data**, or an existing sourced rule.
Opaque `ELAI-01` through `ELAI-06` identify successful read-only inspection groups;
`DLAI-01` through `DLAI-06` identify the effective data and their private hashes.
The address/symbol map, query receipts, equation closure, script inventory and
registry audit stay in ignored `out/research/walk-land-ai/`. Failed symbol lookups
are excluded. Lua APIs, logical script paths, XML tags and equation names below are
the authored mod interface, not engine symbols. Stock names and constants are data
examples: implementations must load the selected player's closure and scripts.

The rule groups follow dependencies: setup, perception, proposal, selection,
landing, execution, free-unit policy and outcomes. They do not impose an order
between independent plan threads. The shared schedule is
[frame service schedule](../frame-service-schedule.md), FS-17 and FC-37;
WTA-01/02 describe the shared player systems and freestore pumping. Exact land
capture/landing/destruction races and land-only timer admission remain U-WLAI-1.
No new frame-order trace is claimed here. A script's `Sleep` or blocking timeout
is a script decision, not an engine service period.
