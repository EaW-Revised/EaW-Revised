# Galactic space battles: the tactical side

FoC galactic conquest, researched 2026-10-07 (M3 planning wave 3). Scope: what happens inside
a **space** battle that the galaxy starts. It begins after the galactic layer has admitted a
conflict and chosen to fight it (the [movement/control walk](gc-movement-control.md),
WGM-41..54) and ends where the galaxy reconciles the result (WGM-55..64, WGM-78..82). Between
those two boundaries this walk maps the map and scene the battle loads, how the persistent
fleets are split into starting forces and reinforcements, what the planet contributes (station,
orbital and planetary structures, upgrades), what differs from a space skirmish, retreat, the
state of the galaxy while the battle runs, and the record the battle leaves for the return.
Land battles are listed only where a shared routine branches by layer; land battles are
auto-resolved in M3. Auto-resolve itself is the auto-resolve walk's subject.

Sources are **debug build** (opaque evidence IDs EGT-01..EGT-25, EGT-S3-01..08 and EGT-SEAM-01..07), **XML data** (EGT-D01 is a
type-name checksum scan of the 71 stock `_space_planet*` maps; EGT-D02 is the authored
GC battle objectives plot), existing sourced behaviour notes, and **unverified**. The private
address map and raw outputs stay in ignored research storage. Authored values below are loader
inputs, not engine literals. No retail capture was made for this walk. There is no galactic
code in the remake, so every GC rule is **missing**; where a rule reuses tactical behaviour the
remake already implements, the row says "same as" or "differs" and names the module.

## Evaluation boundaries

The battle is a child mode retained under the galactic parent (WGS-44, WGS-68). The tables
follow the causal order: the conflict hands over (WGM-48), the sub-mode transition loads the
map and builds the scene once, the battle runs frame by frame in the tactical engine, and the
end hands control back (WGM-59). Inside the scene build the order is exactly the inspected
order; it is load-time work, not per-frame work.

## Frame schedule clarification

The [galactic frame schedule](../galactic-frame-service-schedule.md) records the
WGT-01/02 freeze boundary as GFS-16/GFD-19: child time is not parent travel,
production or fiscal time. GFSC-12 tests retained parent time and reconciled
presence on return. GFD-18/20 retain a separate unknown for the first resumed
parent service inside or after the return frame (GFS-U07); a retained-parent
lifecycle alone does not settle that intra-frame boundary.

GFS-17/18 and GFD-18/GFSC-15 settle ordinary new space-conflict admission: the
arrival frame reaches the resolver and announces combat, while choice happens
on a later eligible invocation. This is a state boundary, not a universal
one-frame loading delay for every space/land or pre-existing pending conflict.
GFS-20/GFD-26 and GFSC-18 settle the retained-active-galaxy pause boundary:
arbitration pause is read at final timer advance after the tail, while an already
due fiscal window is still admitted after conflict work. If a load already
selects the child before the fiscal clock read, GFS-U07 retains that separate
active-mode qualification.
