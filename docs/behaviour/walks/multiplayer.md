frame advances one logical step. A send interval groups frame reports and execution
boundaries; it is not a multi-frame simulation step.

## Scope and order

This walk follows lobby/start interfaces, input and event service outside the logical gate,
frame admission, scheduled command execution before mode service, end-frame checks and
quitting-player processing. Space tactical object/behavior order belongs to
[frame order](frame-order.md); loading, results and credits belong to
[battle flow](battle-flow.md); map/roster/option consumers belong to
[skirmish setup](skirmish-setup.md). Land/campaign internals, online account services and a
compatible original packet protocol are outside this inventory.

Rows are grouped by dependency so that timing terms precede their command consumers.
Within an admitted frame the order is MP-07, battle service, MP-21–MP-25, then MP-36–MP-38.
MP-39–MP-42 run before the battle; MP-32–MP-35 can run while admission is blocked.
All numeric constants below are code constants unless explicitly attributed to XML or an
inherited rule. Packet widths describe evidence, not a requirement to copy the original format.

For the comparison, **same** means the stated semantic interface exists, **differs** means
the remake implements a different policy/representation, and **missing** means the network
behavior or its qualification is absent. Same does not claim a working network session.
`G1`–`G5` refer to the gap ownership table below; an intentional internal difference still
needs the scope check to qualify its visible behavior.

## Session, timing and command admission

Let `F` be the current logical frame, `R` the report/send interval in frames, and `A` the
permitted frame lead. These are separate quantities. Logical time is always 30 frames per
game second; default speed targets 30 frames per wall second.

## Implications for the multiplayer scope check

The relevant contract is a shared initial setup, a complete agreed command stream before
each step, commands before battle service, responsive local feedback while waiting, agreed
speed/time policy, and deterministic departure. Preserve those visible boundaries and FoC
performance. Original packet widths, sparse additive checks, global draw streams and serial
object iteration are evidence about FoC, not reasons to discard explicit typed commands,
canonical SHA-256 state or deterministic partitioned work.

At the original audit, the replay/session foundation did not provide peer readiness,
setup/content agreement, disconnect ownership or recovery. The 2026-10-13 LAN foundation
now supplies sealed-input readiness, setup/content agreement, agreed departure and
desync diagnostics/freeze. Adaptive timing, shared speed and genuine reconnect/resync
remain the separate online work above. Existing 1/2/4/8-worker hash
equality qualifies scheduling within its tested environment; this walk supplies no new
MSVC/GCC/Clang or cross-host/architecture result. Keep compiler/host replay qualification,
local-input reachability and complete script state on the scope-check checklist
(legacy EAWR-1285). Checkpoints and reconnect remain separately designed extensions until their
original availability and product policy are settled.

For impact on an eventual shared M2 battle, prioritize missing-input admission, shared
setup/content identity, selection/coordinate order scope, numeric/script determinism, and
departure ownership. These are later multiplayer concerns; none changes the current M2
release boundary.
