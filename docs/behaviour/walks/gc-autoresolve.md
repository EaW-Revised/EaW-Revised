# Galactic auto-resolve walk

FoC galactic conquest, researched 2026-10-07 for the M3 plan. This walk maps how FoC resolves a galactic conflict
without loading a tactical map: when auto-resolve is offered, forced or unavailable, how the solver gathers the two
sides, the strength model, the single combat round, the winner rule, loss allocation (units, transports, heroes,
stations, structures), retreat, the battle record handed back to the galaxy, and what the player sees and hears.
Land conflicts are auto-resolved only in M3, so this walk sits on the M3 critical path.

It does not repeat the conflict admission, arbitration, tactical handoff and return rules of
[gc-movement-control.md](gc-movement-control.md) (WGM). Where a rule refines a WGM rule it says so. Persistence is in
[gc-session-save.md](gc-session-save.md) (WGS); the galactic AI's use of conflict results is in [gc-ai.md](gc-ai.md)
(WGA). The Ours column identifies implemented arithmetic and explicit integration seams; a missing entry remains a gap.

There are 84 rules (WAR-01 to WAR-84). All but the items in the [unverified list](#unverified-and-capture-plan) come
from debug-build readings, with stock values from the effective FoC XML. No retail capture was made for this walk.

## Evidence and scope

Evidence IDs EAR-01 to EAR-61 are debug-build readings kept in the ignored research store of this branch; EAR-X1 is
the winning effective FoC XML (`gameconstants.xml`, `aiterraineffectiveness.xml`, the campaign, story, unit and GUI
dialog files). Values below are authored stock values unless marked "code".

One solver instance serves the whole game. A galactic conflict service drives it in four steps per conflict:
prepare (space or land), add combatants, initiate, then one or more combat-round calls until the round reports
"done" or "done with a retreat", then cleanup. A tactical (mid-battle) entry point uses the same solver with a
different gatherer (WAR-17). Everything in the solver runs inside the galactic conflict service of one frame; it
consumes draws from the synchronized game random stream only during loss allocation (WAR-41).

Integration targets, used in the gap matrix:

- **new GC conflict service** (the WGM conflict state machine, conflict handoff (legacy EAWR-1115)) owns arbitration, timers and outcome
  application;
- **new auto-resolve solver** (engine-free, in the galactic sim layer of E3-0a) owns gathering, strength, the round
  and loss allocation;
- existing **AI contrast data** (FH-30 in [foc-tactical-ai.md](../foc-tactical-ai.md), ours
  `src/script/foc/host.hpp` `average_contrast`) and the unit/type tables (AI_Combat_Power, CategoryMask, company,
  squadron and spawned-unit data);
- **GC return** (WGM-55..64, tactical return (legacy EAWR-1116)), **story** (E3-3), **galactic UI** (E3-4, WGUI) and **save/replay**
  (WGS, E3-6).

## Strength model

Integration: **new auto-resolve solver** reading the validated type tables; the contrast factor is the existing FH-30
lookup.

| ID | Rule and conditions | Source | Ours |
|---|---|---|---|
| WAR-19 | A type's power is its `AI_Combat_Power`. In galactic mode the raw value is used. In a tactical mode (mid-tactical auto-resolve) a company or squadron whose first member creates a team is scaled by clamp(`Max_Squad_Size` / member count, 0, 1). | debug build EAR-51 | tactical scaling same as the scoring consumer's first-member team clamp (registry `Create_Team` partial); galactic raw value missing |
| WAR-20 | A combatant's type: a planet uses its base type. Otherwise start from the object's original type; for a transport, take the first transport content whose type names a unique space container unit (space) or unique ground container unit (land); for a non-transport, the first ground company member with such a container. If the object's current type has more power than the chosen type, the current type wins. In space the result is replaced by its unique space container unit, on land by its unique ground container unit, when it has one. | debug build EAR-03, EAR-13 | missing |
| WAR-21 | A side's force is a vector: entry 0 the ground total, entry 1 the space total, then one entry per contrast category in the contrast list's order (each entry knows its category and whether it is ground). Every power below is added to the **first** category entry whose mask intersects the type's `CategoryMask`, and only inside that matching branch to the layer total (space total in space, ground total on land). A type with no matching category contributes to neither category nor total; do not add an unconditional total alongside category matching. | debug build EAR-03; G4-AR01 | missing |
| WAR-22 | On land the planet entry contributes only its persistent built tactical structures (each structure type's power to its first matching category and, in that branch, to the ground total). This planet branch skips both the garrison block and the planet/base's own power and weakest-unit selection. | debug build EAR-03; G4-AR01 | missing |
| WAR-23 | Outside the land-planet branch of WAR-22, a galactic object (not living in a tactical mode) contributes its garrison: for each spawned unit type selected for the owner's tech level (WAR-77), starting count × power through the category gate of WAR-21. A starbase in mid-tactical has no garrison. Stock starbases and structures author these through `Starting_Spawned_Units_Tech_N`. | debug build EAR-03; G4-AR01/03; XML EAR-X1 | missing |
| WAR-24 | Outside the land-planet branch of WAR-22, the combatant itself contributes its type's power through WAR-21, except a transport in space that is not a named hero. Among those eligible combatants the one with the lowest power (strictly lower, first found wins ties) is the side's **weakest unit**. This selection precedes category matching: an eligible combatant can become weakest even when its category matches no force entry. | debug build EAR-03; G4-AR01 | missing |
| WAR-25 | Per side, scanning its combatants in order, the last whose hero type is a superweapon becomes the side's superweapon and the last that contains a superweapon killer its superweapon killer. WAR-79/81 specifies the type source and member tests. | debug build EAR-14; G4-AR05/07 | missing |
| WAR-26 | Hero bonuses: before attacking, each side builds a 32-entry table of category bonuses from its combatants that have special abilities. Query abilities on this hero type with the corresponding hero object and conflict planet as context. A `Combat_Bonus_Ability` reports its `Unit_Strength_Category` mask with factor 1 + `Health_Bonus_Percentage` + `Damage_Bonus_Percentage`; an `Enhance_Defense_Ability` reports factor 1 + `Enhancement_Percentage`; other abilities report nothing. ## The combat round

Integration: **new auto-resolve solver**. One round decides the battle; the round is timed for presentation only.

| ID | Rule and conditions | Source | Ours |
|---|---|---|---|
| WAR-27 | Space shortcut at initiate: when neither side has a superweapon and both sides' space totals are ≤ 0, the side with more combatants wins without a round, the other side retreats (WAR-46), and the battle counts as fought. Equal counts: the defender (non-aggressor) wins. | debug build EAR-01 | `src/campaign/auto_resolve_round.cpp`: pure round space shortcut |
| WAR-28 | Round timing: the round runs at the first combat-round call after `AutoResolveDisplayTime` × **0.6666** (code) seconds of logical time since prepare, or at once when a retreat is in progress or the caller forces it (the instant path forces it). If it runs early the start frame is moved back so the display completes on schedule. The battle is fought only once. | debug build EAR-02; XML EAR-X1 | `src/campaign/auto_resolve_round.cpp`: `step_auto_resolve_round` |
| WAR-29 | Attrition factors: winner and loser factors are `AutoResolveWinnerAttrition` (**0.75**) and `AutoResolveLoserAttrition` (**0.80**), or `RetreatAutoResolveWinnerAttrition` (**0.50**) and `RetreatAutoResolveLoserAttrition` (**0.65**) when a retreat is in progress at round time. | debug build EAR-02; XML EAR-X1 | `src/campaign/auto_resolve_round.cpp`: round rules and attrition selection |
| WAR-30 | Each side attacks the other: side A's combatants attack a copy of side B's force vector (giving B's remaining force), then side B's attack a copy of A's. A side's attack: the bombing run first (when this side is the bombing side and a bomber type is set, the bomber type's power attacks once), then each combatant in order. | debug build EAR-02, EAR-04 | `src/campaign/auto_resolve_round.cpp`: `auto_resolve_attacks` |
| WAR-31 | A combatant attacks with **one** contribution: on land the planet entry attacks with its first positive-power persistent built structure; otherwise a galactic object with a garrison attacks with its first positive-power garrison unit whose selected starting count is positive; otherwise the combatant attacks with its own type's positive power (a transport in space that is not a named hero does not attack). | WAR-33 | Hero bonus on the attack: over the attacking type's category bits, the largest table value + 1 (WAR-26) multiplies the attack power when any bonus applies. | debug build EAR-07 | `src/campaign/auto_resolve_round.cpp`: attack hero factor |

| WAR-36 | Superweapon pressure before the winner: when side A has a superweapon and side B has no superweapon killer, side B retreats; otherwise when side B has a superweapon and side A no killer, side A retreats (first retreat wins, WAR-46). | debug build EAR-05 | `src/campaign/auto_resolve_round.cpp`: round superweapon pressure |
| WAR-37 | Winner: during a retreat the non-retreating side wins. Otherwise sum all positive entries of each side's remaining vector (totals and categories alike). ## Loss allocation

Integration: **new auto-resolve solver**; deaths go through the ordinary GC death path so hero respawn (WGM-78..80),
story defeat and scoring see them.

| ID | Rule and conditions, in order | Source | Ours |
|---|---|---|---|
| WAR-38 | The winner player is recorded first. Space transport losses for the loser (land: none): N = loser transports; survivors allowed K = 0 when N is 1, else round(N × (1 − `AutoResolveTransportLosses`)) with `AutoResolveTransportLosses` **0.333333**; K = 0 when the loser's faction is not playable. Transports carrying a named hero escape first (up to K, removed from the loser's list); the remaining transports in list order survive while slots remain and die otherwise. Only the escaping hero transports are removed from this queue: ordinary survivors and killed transport entries retain their positions for WAR-41 picks. Classification after lethal delivery is the WAR-U04 outcome seam; do not silently delete dead entries. When any transport survives or escapes, the loser retreats. | debug build EAR-02, EAR-20; XML EAR-X1 | `src/campaign/auto_resolve_round.cpp`: transport requests and PostTransportDeathRoster seam |
| WAR-39 | Attrition of the computed losses: in the battle layer, each side's remaining force gains back (total − remaining) × (1 − attrition factor) (WAR-29).
