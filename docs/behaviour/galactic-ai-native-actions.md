# Native galactic AI action layers

The native runtime prepares galactic writes in private action layers. The galaxy owner remains unchanged during AI decisions. A read adapter borrows unchanged snapshot columns and projects changed fleet, actor, surface, producer and account rows. Static population and income schemas are frozen at session creation; each barrier freezes its graph and fiscal inputs before decisions. Inherited columns resolve directly to immutable owners, so effect count does not deepen snapshot lookup or destruction. No ECS scene is cloned.

The pass has three ordered parts:

1. A serial prelude runs the existing `begin_galactic_barrier` completion work: target reconciliation, blocked operations and task-force events. Completion can cancel a paid task or release an invasion reader for any player. The prelude is frozen before player decisions start.
2. Player layers run in ascending player ID. While the pass remains sequential, a player inherits the prelude and every lower-ID player's effects. Mutable action rows belong to the current player; predecessors are immutable.
3. A serial tail inherits every player layer. It contains deferred attaches and events, then the commands handled by `after_service`, including freestore movement. The tail commits last, after `after_service` has finished.

The prelude and tail are explicit serial boundaries that the parallel-player work in S9 must retain or replace deliberately. Moving their writes into another player's turn changes visibility, allocation or journal order.

The final ordered commit validates the complete predecessor and entity-ID chain before changing the galaxy. Funding, movement and actor notifications prepared during decisions are delivered once. Native effects retain their original journal order. During prepared replay, logical publications borrow the staged columns while retaining the exact event prefix for each boundary. One full snapshot is built after the ordered effects; a barrier without a logical publication keeps its existing snapshot. Checkpoints and native hashes observe completed barriers.

This validation covers the chain's ownership, ordering and identity frontiers. Effect replay still checks each action against the live owner in order; a failure can follow already-applied effects and makes the barrier's session unusable. A failed prepared replay retains the coherent pre-barrier snapshot for post-mortem reads; it does not roll back partial owner writes. It is not an all-or-nothing world transaction.

World service requires a completed native barrier: a step requested during staging is rejected without changing the owner. Capture and due-corruption feedback runs only in the later committed world service, never for a staged surface arrival or credit change.

Each current shadow, including its lazily materialized read publication, belongs to one decision thread. Before handing reads to another thread, the owner materializes the publication and shares the immutable snapshot pointer. Concurrent reads of an unfrozen shadow are outside this contract; S9 must freeze these publications before parallel player work. Read-only fleet lookups do not mark fleet rows as written or copy the full fleet publication column.

Ordinary actions reuse the player's sparse layer. Journal appends retain its cached publication without forcing a new read projection. Phase boundaries and immediate transactions freeze predecessors; sparse reads traverse fewer than 32 links before a checkpoint of written rows. This storage bound does not restrict authored objects or action values. Empty immediate transactions consume one request from the barrier budget, bounding retained boundaries as well as ordinary actions. Player and ordinary continuation layers use the barrier request bound; live-object growth retains its separate object bound. The replay chain retains every ordered effect. A diagnostic atomic flag catches foreign-thread routing in debug builds, and a weak thread context expires safely after barrier destruction. Foreign destruction requires a quiescent creator and aborts its session; it is not concurrent owner access.

Staged views inherit `economy_forecast`, `production_offers` and `income` until authoritative reprojection; paid admission uses its explicit sparse population and income-source projections.

Private Lua immediate transactions keep their existing grouping: prepared creations apply before absolute account balances and their credit-victory projection. A transaction is published as one batch even when its Lua calls interleave creation and money operations. Its freestore and funding publication boundaries remain intact.

Ordinary publication details also remain significant. A refused paid request can refresh private population counts without publishing them. Cancelling a paid task publishes its refund before publishing queue removal; the outcome notice sees the refund publication. Appending an effect to the native journal does not publish world state. The staged adapters retain these boundaries. If the last paid request only refreshes private counts, the completed snapshot retains the last published counts while the galaxy owner keeps the refreshed values for the next request. Its derived generation key remains distinct from that immutable publication.

Movement, launch, landing, paid queues, credits, direct creation, task cancellation and invasion records use the same admission calculations as their live counterparts. Synthetic contracts compare staged reads and receipts with a live oracle, check that the galaxy stays unchanged before commit, and compare committed state and continuation at 1, 2, 4 and 8 workers.

Native orbit rechecks also belong to the current player layer, including the terminal no-hop recheck after ordinary movement arrives. WGM-153/154 retain their relink, inbound gather, conflict event and listener order through a shared movement kernel. Listeners observe the preceding publication; later reads in the same chain and inherited player layers observe the completed recheck. Commit replays the existing `orbit_recheck` effect without replacing the barrier's base during decisions or building a full snapshot per recheck. Arrival, gathered attacker/defender filtering, record bytes and continuation after restoring with a different worker count are compared with an unbatched oracle. A genuinely stale base still refuses before replay. These staging rules do not change the separate synchronous Lua result or conflict-end wait contract.

The mixed-owner reader rules WGS-186..188 also apply to staged actions. Surface links retain the existing owner prefix, and invasion defense reads target allegiance unless a ground base supplies the defender. Sparse control adapters resolve that state by planet identity, independently of their selected surface-row positions. Caller ownership safety stays outside the link operation.
