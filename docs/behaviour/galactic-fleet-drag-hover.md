# Galactic fleet drag hover

| Rule | Behaviour | Evidence |
|---|---|---|
| GFDH-01 | While an overview fleet icon is held, the hovered fleet icon shows its authored mouse-over quad at the source planet, or at another planet when a hyperspace path is available. A held overview ground-force icon admits a fleet icon only at its source planet. The quad is additive over the stack, uses the `g_planet_fleet` component's `Mouse_Over_Texture_Name`, and is independent of whether release ultimately accepts the drop. An empty slot selects the third authored mouse-over entry; a populated icon the first. | Debug build overview hit test, hover admission, fleet display update and button rendering; effective command-bar data. Retail capture (Remake, GTX rig, 2026-11-25): the hovered empty slot's visible rim turns from blue to red. |
| GFDH-03 | While an overview fleet icon or ground-force icon is held, every planet whose hyperspace path from the source exists (the source included) shows its empty orbit slots, not only the hovered planet. Each empty slot draws the component's first `Blank_Texture_Name` entry (the base texture) tinted RGBA 25, 85, 151, 255, a fixed drop-slot colour in the engine rather than the faction colour. A held fleet uses its own path admission; a held ground stack the path with no fleet. | Debug build galactic fleet display update (per planet: hyperspace path from the drag source, then every empty orbit position gets base texture 0, mouse-over texture 2 and the colour above); retail capture (Remake, GTX rig, 2026-11-25): lifting a fleet at Yavin shows blue empty rings at Arda, Vjun, Celanon and Yavin before the pointer reaches them. Partial in the viewer: the debug build also hides a planet's slots when the held fleet may only raid it, or could move there only by activating an ability; the viewer has no producer for those two admissions yet. |
