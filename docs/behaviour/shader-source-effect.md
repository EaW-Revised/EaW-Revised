# Native source effect contract

This is EAWR activation policy, not a claim about retail source lookup or a
qualification of installed mod effects. Activation remains off pending SOURCE-C.

- **SFX-01 — bounded graph.** The native token parser retains ordered global
  declarations, types, semantics, defaults, annotations, sampler assignments,
  techniques, passes and duplicate state assignments. Cleanup passes stay in
  order; this parser does not infer draws or choose techniques. Caller budgets
  bound input bytes, tokens, structural nesting and graph nodes independently.
  Unknown effect syntax, unresolved shader objects and unsupported compile
  arguments refuse; function bodies remain compiler-owned HLSL.
- **SFX-02 — owned descriptors.** Parser-identified effect wrappers are blanked,
  preserving executable HLSL and newlines. Individual exact entry/profile pairs
  compile from that single expanded input through SOURCE-A, without another
  preprocess. A heap owner retains all graph, string, packed-default and program
  storage; P1 views remain valid when its handle moves. Numeric literal defaults
  use logical row packing, independently of CTAB register padding. Class-three
  matrix defaults, arithmetic defaults, structures and object arrays currently
  refuse. Numeric literal constructors/lists and scalar parameter state
  references are supported; other expressions remain in the graph and yield a
  located unsupported result, never fake expression bytecode.
- **SFX-03 — shared consumers.** Supported source state spellings map to the
  existing measured P1 identifiers used by S-17/S-19. P3/P4/P5 retain binding,
  domain validation, technique compatibility, fixed-function capability and
  execution policy. Unsupported state spellings/selectors refuse. Named shader
  objects, sampler texture references and parameter evaluation links use the
  same P1 descriptor graph. No second renderer state implementation is added.
- **SFX-04 — selection.** Resolve effective compiled input first across the
  mounted VFS; only genuine absence permits effective mod source. An existing
  corrupt compiled input remains selected. Caller supplies contributor-aware
  mod identity and opt-out queries before acquisition or cache access. Source
  presence/refusal uses explicit omission or a same-name hand-adapter
  approximation, never the genuinely missing-resource material policy.
- **SFX-05 — source cache closure.** P7 cache keys additionally bind root/include
  source, layer and origin and an explicit native parser schema. The source
  identity hook records the ordered dependency ledger, macros, exact stages,
  stage-text digest, expanded digest, preprocess manifest and SOURCE-A compiler
  contract plus verified package/ABI/capability identity. P7 still owns payload
  validation and user-data persistence; backend owners supply their existing
  emitter/admission identities. Resolve afresh before lookup; opt-out also
  excludes warm outputs. Source identity is not a renderer admission receipt.
  SOURCE-A supplies an ordered dependency ledger rather than include edges;
  each P7 include parent denotes the activation root. The expanded digest binds
  the actual preprocessing context in addition to every effective dependency.
- **SFX-06 — diagnostics.** Reports contain typed reasons and logical locations,
  never source/generated text or compiler message bodies. Known logical input
  line directives retain coordinates; unknown mappings omit line/column. Program
  offsets are never presented as original source coordinates. Compiler profile
  refusals remain exact; no profile promotion or proprietary fallback exists.
- **SFX-07 — activation boundary.** Parsing/compilation and cache regeneration
  belong to mod activation workers. No player-time Python, draw-thread compile,
  mod writes, generated source redistribution, GPU qualification or activation
  switch is introduced. SOURCE-C owns installed and visible acceptance; the
  installed preferred PS1.1 capability gap remains unqualified.
