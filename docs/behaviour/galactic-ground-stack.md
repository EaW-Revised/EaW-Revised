# Galactic overview ground stack

The debug-build ground-control walk qualifies these rules independently of the
three orbit stacks. Private initialization, status, positioning, pointer and
encyclopedia evidence is retained outside the committed tree. The source
boundaries of [WGUI-15/41/54/55](walks/gc-ui-sensors.md) still apply.

| ID | Rule | Evidence |
| --- | --- | --- |
| GGS-01 | Each planet has one `g_planet_land_forces` control in addition to its three orbit controls. Position it at the projected planet point, shifted upward by this component's `Offset` Y. Its own `Size` X scales the foreground image; `Offset` X supplies the stack-layer lift. | debug build: overview initialization, transport positioning and picking; effective command-bar XML |
| GGS-02 | An inaccessible surface has no ground stack. Otherwise ground contents or count knowledge admits a nonempty landed force, including an unallied planet whose ground count is known. Unknown ground counts remain hidden. The stack counts the current planetary allegiance's faction, independently of the three orbit positions; the tooltip's separate allied-content predicate is GGS-03. Stack texture is the capped ceiling of count divided by the stack constant under WGUI-92. The ground image compares live transported payload types by tactical health; the existing hero-filter ranking branch also applies. | debug build: status update, stack image setup and representative selection |
| GGS-03 | Hover uses the ordinary delayed encyclopedia. Its header uses the faction's localized land-garrison title, followed by landed types allied to the planet owner; count-only entries disclose counts without type details. The viewer submits existing `LaunchFromSurface` and `LaunchFleet` commands and revalidates every carried local identity against the current published snapshot. | GGS-09 | The display projection separately publishes the permitted health winner and hero candidate for each admitted ground stack. It filters live transports to the planetary allegiance's faction, regardless of faction names or ordinals. For a transport it compares live payload current types; template members never substitute for live contents. A contained named hero supplies its current type, found by the first live recursive membership match. The local hero preference chooses the hero candidate when available, otherwise the health winner; ordinary preference reverses that fallback. Ground-size knowledge permits these images independently of contents knowledge and grants no object identity, launch permission or typed tooltip cell. | debug build: representative selection, true-type and contained-hero walks; effective `Tactical_Health`, `Is_Named_Hero`, `Is_Generic_Hero`, `Ranking_In_Category` and icon data |

The viewer creates this control from immutable observer-filtered snapshot facts
and effective component art. It retains the badge across publications and uses
the ordinary HUD selection, drag ownership and encyclopedia lifetime. `TransferSurface` (galactic opcode 25) carries ordered surface identities and a
source-to-destination path. The simulation resolves generated fleet identities;
`FleetMotion.land_on_arrival` retains the request independently of transit and
is included in movement encoding and checkpoints. No new timer or service
cadence is introduced; the existing partitioned movement stage and ordered
arrival commit own it. State/replay/checkpoint versions change with this field.

receipt alone never qualifies the visible ground control or its drag result.
