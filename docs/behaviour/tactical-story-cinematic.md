# Tactical story cinematic camera, screen fades and environment calls

The Lua calls a battle script uses to run a story cinematic: `Start_Cinematic_Camera`, `End_Cinematic_Camera`, the four camera and target key calls, `Transition_To_Tactical_Camera`, the four fade calls and the two environment calls. Rules `TSC-nn`.

## Applicability

FoC (debug build, one headless walk of the registration, argument checks and camera-key handling of each call, plus the community function list for the argument names), the tactical script host (`tactical_story`, `tactical_object` and the plan and evaluator hosts that read the same registration table). The galactic hosts are a separate row set and are not covered. Evidence cells say "debug build". Not observed: any played run of a stock story cinematic; every statement about what the player sees comes from the walk, and the places where our picture is a reading are marked **unverified**.

## Interface

A call stages one command of one of three presentation verbs of the host. The session hands the command, with the tick of the script service that made it, to the viewer in script order. The viewer draws it. Nothing reaches the world.

| Verb | Staged by | Arguments (text) |
|---|---|---|
| `foc.story_camera` | the camera, target, start, end and return calls | `start,<music>`; `end`; `tactical,<seconds>`; `camera|target,set|transition,<x>,<y>,<z>,<seconds>,<distance>,<pitch>,<yaw>,<euler>,<object or ->,<use rotation>,<centre>` |
| `foc.story_fade` | the four fade calls | `out|in|on|off,<seconds>` |
| `foc.story_environment` | the two environment calls | `index,<n>` or `cinematic,<0|1>` |

## Rules

| ID | Rule | Evidence |
|---|---|---|
| TSC-01 | `Start_Cinematic_Camera([music])` starts the story camera. The optional value is a Lua boolean, default true; any other type is a script error. The camera and the target each get one key at the pose the player's camera has now, the cinematic's own clock starts at 0, and the clock counts logical frames (30 per second). While it runs the command bar, radar, fog-of-war overlay, occlusion silhouettes and the mouse pointer are off, and localised sound events are muted. `music` true restarts the mode's ambient music. `End_Cinematic_Camera()` drops the keys and gives all of that back. Our reading: the story camera drives the movie camera path of the battle (the same one the battle cameras and the other cinematics use), the battle UI, fog overlay and world input go like those cinematics', the story camera is meant not to raise the letterbox bands (the script asks for them with `Letter_Box_In`, which the stock scripts call first). The story camera does not raise movie-camera bands; whether the original shows bands without `Letter_Box_In` is **unverified** and is on the fidelity list. The music restart and the sound muting are not wired (**unverified**, fidelity list). A camera call made while no cinematic runs is ignored, as in the original. | debug build |
| TSC-02 | `Set_Cinematic_Camera_Key(position, distance, pitch, yaw, euler, object, use_object_rotation, centre)` and `Set_Cinematic_Target_Key(...)` (same eight values). Fewer than eight values is a script error. A first value that is not a position (an object is a position) is a **warning** and the call does nothing. The next four numbers and the two flags must be numbers (a script error otherwise); a flag is true above zero; an object value that is not a game object is ignored. The call drops every key of its track and places one key at the current frame that cuts (no blend). With `euler` the offset is built from a vector of length `distance` pointing back along -Y, turned up by `pitch` degrees about X (a positive pitch lifts the camera) and then about Z by `yaw` degrees; without it the three numbers are the offset itself. An unattached key is at position plus offset; the track remembers that point as its last position. | debug build |
| TSC-03 | `Transition_Cinematic_Camera_Key(position, time, distance, pitch, yaw, euler, object, use_object_rotation, centre)` and the target twin (nine values; the time follows the position). When `time` is longer than one logical frame, the track's keys are replaced by two: a start key at the current frame at the track's last evaluated position, and an end key `floor(time * 30)` frames later at the new position plus offset (attached to the object when one is given). Both keys blend linearly with ease 0.5 at each end (TSC-07). A time of one frame or less is the Set call. The track's "last position" is the pose it showed in the last frame, so a transition begun in the middle of another starts where the picture is. | debug build |
| TSC-04 | `Transition_To_Tactical_Camera(time)` goes from the pose the cinematic shows now to the player's camera over `time` seconds (a number, a script error otherwise; at least one frame). Both tracks are replaced by a start key (ease 0.25) and an end key (ease 0.25) at the player's camera position and look-at point, and the cinematic's clock restarts at 0. The cinematic then holds the player's pose until `End_Cinematic_Camera`. The original first sets the player's camera to its farthest zoom at once and returns to that pose; our player's camera is taken as it is now, so there is no zoom reset (**unverified** whether the stock scripts rely on it; fidelity list). | debug build |
| TSC-05 | A track is read at the cinematic's frame f: no key is the origin; one key is that key's position; before the first key, the first key; between two keys k1 and k2 the position is a blend by TSC-07 of the two key positions with the ease-out of k1 and the ease-in of k2 (a cutting k1 gives its own position); after the last key, the last key. The picture is the camera track's position looking at the target track's position. The original adds a camera-shake effect set, a roll, a lag and an overshoot prediction, and keeps the camera above the terrain in land battles; none of them is set by these calls (their defaults give the plain picture) and none is drawn here (**unverified**, fidelity list). | debug build |
| TSC-06 | An attached key follows its object: the object's position plus the key offset; when `use_object_rotation` is set the offset is turned by the object's drawn orientation first, otherwise it stays in world axes; the object type's ranged-target height adjustment is added in both cases. With `centre` set the key aims at the object's drawn centre (its first fire-bone, else its bounds centre) plus the offset, unrotated. An object that no longer exists leaves the last orientation and height it had; a key that never had an object to read holds the track's last position. Our reading of the drawn orientation is the turn about the vertical axis of the unit as drawn; pitch and roll are not read, and a unit the local view does not draw counts as gone (**unverified**, fidelity list). | debug build |
| TSC-07 | The blend fraction for a time fraction t between two keys is a speed ramp: with `a` the ease-out of the first key and `b` the ease-in of the second and `s = 2 / ((1 - b) + 1 - a)`, the distance is `s t^2 / (2a)` for t below `a`, `s a / 2 + (t - a) s` up to `1 - b`, and then the rest of the way down the ramp so that t = 1 gives 1. Zero eases give t itself. Covered by `camera_story_contracts`. | debug build |
| TSC-08 | **Presentation only.** None of the calls moves the simulation. A call is not a world command: it is not recorded in the replay, saved, hashed or routed as input. A headless run makes the requests and nobody takes them. The viewer's state (the cinematic, the fade, the kept environment request) is not saved: a battle restored mid-cinematic starts with the picture and the fade clear, and the script's own later calls are no-ops until it starts a cinematic again (the original keeps its fade state in a save; **unverified** for the cinematic mode; deviation, fidelity list). Covered by `foc_ai_contract_tests` (`story_presentation_contracts`): the world hashes of a script that makes every call equal those of one that makes none, at 1, 2, 4 and 8 workers, no replay command is recorded, no request becomes next tick's input. | tests; debug build for the camera FX state a save holds |
| TSC-09 | **Multiplayer.** The scripts run in lockstep on every peer and make the same requests in the same tick (the contract test compares them at 1, 2, 4 and 8 workers). Each peer draws its own presentation from them; nothing a peer draws is hashed or sent. A peer that joins late or restores a battle (not offered mid-battle) would miss the picture, not the match. | tests |
| TSC-10 | **Clock.** A key is placed at the script service tick that made the call (the script's own timeline: its `Sleep` runs on the same ticks) and the cinematic is read at the presented battle tick, 30 ticks per second, so a transition is as long as the script's waits whatever the game speed; pause stops it. The fade (TSC-11) runs in render time as the original's fade timer does. The battle pacing request the other cinematics make is not made (**unverified** that the original paces; fidelity list). | debug build |
| TSC-11 | `Fade_Screen_Out(seconds)` clears a black full-screen layer and raises it to opaque over `seconds`; `Fade_Screen_In(seconds)` makes it opaque and lowers it to clear; the opacity is linear in time; the layer keeps its last state until the next call (a script that fades out and never in leaves the screen black). `Fade_On()` is opaque at once, `Fade_Off()` clear at once. The seconds value is a number (a script error otherwise, also when it is missing). A time of zero ends at once. The layer covers the whole battle picture, the UI included. Covered by `ui_model_contracts` (`ScreenFade`). | debug build |
| TSC-12 | `Set_New_Environment(index)` takes one number (a script error otherwise) and truncates it to an integer; `Set_Cinematic_Environment(on)` takes one Boolean. Both are only valid in a tactical game (a script error elsewhere). The effect is the environment selection of R-SEL-06 and R-SEL-07 of the TED environment note: the index is clamped to the map's records; `Cinematic` is the record named exactly so, and turning it off restores the index it replaced. **Not drawn:** the viewer's space view composes its sky and light from the first environment record and cannot change record during a battle, so the requests are validated, kept in the viewer's state and not shown (fidelity list; two stock maps carry a `Cinematic` record). | debug build; R-SEL-06, R-SEL-07 |
| TSC-13 | **Effect of registering the calls on the simulation.** Before this rule the tactical script host had none of these functions: a call was a script error that ended the calling thread at that call and rolled back what the resume had staged. A script that made one of them now runs on past it, as in the original. A battle that runs such a script therefore differs in its world hashes from the old behaviour, and a battle whose scripts make none of these calls is unchanged. | debug build (registration); tests |
| TSC-14 | **Not covered here:** the cinematic-mode functions `Start_Cinematic_Mode` / `End_Cinematic_Mode`, `Cinematic_Zoom`, `Create_Cinematic_Transport`, `Play_Cinematic_Engine_Flyby`, `In_End_Cinematic`, `Do_End_Cinematic_Cleanup`, `Promote_To_Space_Cinematic_Layer` and `Start_Cinematic_Space_Retreat` (separate rows of the Lua gap plan), `Lock_Controls`, and the galactic hosts. The tactical plot scripts are not run in a battle by the story engine (HCB-72), so the stock story missions that use these calls are reached only through object scripts (the demo controllers) until that changes. | repo |

## Cases

- **TSC-C1.** `Start_Cinematic_Camera()`, then `Set_Cinematic_Camera_Key(p, 100, 30, 0, 1, 0, 0, 0)` with p at the origin: the camera stands 100 · cos 30° behind the origin along -Y and 50 above it (TSC-02); `camera_story_contracts`.
- **TSC-C2.** A `Transition_Cinematic_Camera_Key` of 4 s to a point 300 away: after 2 s the camera is 150 along, after 1 s it is 37.5 along (TSC-03, TSC-07).
- **TSC-C3.** `Fade_Screen_Out(2)`: after 1 s the screen is half black; it stays black after 2 s until `Fade_Screen_In` or `Fade_Off`.
- **TSC-C4.** `Set_Cinematic_Camera_Key("nope", ...)` logs a warning and the next statement of the script runs.

## Unknowns

- Whether the stock scripts rely on the player's camera zoom reset of TSC-04.
- The pitch and roll of an attached object's orientation (TSC-06), the camera effects and lag (TSC-05).
- Whether the original paces the battle during a story cinematic (TSC-10) and what a save mid-cinematic restores (TSC-08).
- The sign convention of the pitch (TSC-02) comes from the order of the rotations in the walk; no played run was compared.
