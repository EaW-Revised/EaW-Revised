# Source shader compilation

These are project boundary rules for the optional activation compiler. They do
not assert general source-effect or shader-model compatibility. The owner
approved source-only translation with compiled-form preference; selection and
effect-graph integration remain separate work. Activation remains off.

* **SSC-01:** Acquire root and include bytes through the mounted VFS, using its
  effective record and checking its recorded size before opening that exact
  candidate. Includes are case-normalized logical paths. Quoted includes try
  parent-relative then source-root lookup; system includes use source-root
  lookup. Only not-found permits the second lookup. Absolute/drive paths and
  traversal outside the logical source root are refused. The assets provider
  has no dependency on presentation and no independent filesystem scanner.
* **SSC-02:** Supply both public preprocessing callbacks, including during
  stage compilation, so the dependency cannot fall through to host filesystem
  access. Each successful open owns a stable buffer until its exact close.
  Track active ancestry for cycles, and record each open in order, including
  repeated and empty includes. Root/include bytes, opens, depth, identifiers,
  macro counts and accepted expanded/compiled output have separate bounds.
  Callback exceptions become typed refusals and cannot cross the C ABI.
* **SSC-03:** Preprocess the effect graph once with recorded ordered macros.
  The effect parser supplies identified stage text, entry and exact profile.
  Stage compilation applies no macros and refuses further includes. Use public
  HLSL to D3D bytecode, API-version option 1.0 and debug stripping disabled.
  Read the resulting bytecode through the existing effect-program descriptor
  and verify the requested stage and profile before returning owned bytes.
  Reconstruct borrowed views after moves/copies. Existing stage translation
  remains the sole SPIR-V/reflection/backend route.
* **SSC-04:** The versioned source contract binds public HLSL signatures,
  layouts, options and measured scope, plus the verified package closure and
  existing compiler ABI/capability identities. Preprocessing identity includes
  root and every effective dependency logical/layer/archive identity and hash,
  ordered macros and expanded hash. Stage identity adds identified input hash,
  entry and profile. Cache integration must additionally bind the eventual
  effect-parser schema and fresh compiled-first selection; these digest values
  alone are not a complete source-effect cache key.
* **SSC-05:** Invented pass-through VS/PS 1.1, 2.0 and 3.0 controls are a narrow
  capability test, not a universal profile guarantee. The installed source
  capability control's exact pixel-1.1 stage remains a named frontend refusal;
  its vertex-1.1 stage succeeded. Never promote requested profiles or classify
  supplied unsupported source as absent. Fixed alternatives require explicit
  degradation and their own state/admission proof. No proprietary compiler or
  dependency modification is introduced.
* **SSC-06:** Diagnostics retain typed preprocessing/stage/package causes and
  logical root identity. Line/column remain unknown where this boundary cannot
  prove a source mapping; compiled-byte offsets are never source coordinates.
  Raw compiler messages are freed without logging their source-bearing text.
  Expanded source and generated bytes remain in memory/player data. Public
  synchronous calls have no hard internal CPU/heap deadline; cancellation
  checkpoints and callback budgets cannot interrupt compiler-internal work.

See [owned stage translation](shader-stage-translation.md) and
[the pinned package](../shader-runtime-package.md). The native source-effect
graph, selection/opt-out/cache and eventual admission are subsequent seams.
