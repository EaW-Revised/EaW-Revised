# Galactic AI runtime composition

The production `PreparedLiveCampaign::create` path composes these same stock providers for active AI seats. It reads each faction's `AI_Player_Control` assignment, resolves the selected difficulty adjustment through the player XML mappings, and supplies the active human context and directional enemy choice (WGA-02/431, WGS-08/85). Human, inactive and Neutral controllers do not acquire an opponent manager; the existing galactic goal checkpoint validation excludes Neutral goal owners even when a viewer seat is labeled AI. Startup and restore retain the immutable campaign content and space provider; each factory call creates a fresh usability owner. The startup adapter is inline, while admitted live frame work uses the session's selected worker adapter. Immediate script work is bounded by the existing galactic object resource ceiling; this ceiling is an implementation resource limit, independent of authored gameplay values.

The campaign adapter prepares original selection content from the validated catalog and galactic type table, loads the galactic XML and stock Lua closure, and materializes the plan declarations before live ownership. Its fingerprint includes effective original-type values, loaded registry digests, XML and Lua bytes, original IDs, campaign identity and the selected fog policy. These are preparation operations, not planning turns (WGS-134..141, WGA-01..05/25/56).

The prepared perception input also retains the validated campaign's `Is_Story_Campaign` Boolean (WGS-10, WGA-423). `Game.IsStoryCampaign` returns numeric 1 for true and 0 for false, with the value included in the runtime content identity. Production preparation applies `value_or(false)` for an absent authored tag, matching the constructed campaign default and the convention in `src/platform/galactic/live_game_session.cpp`'s story-prevention policy. Its prepared story input is therefore always available; the unavailable-input branch is reachable only through synthetic or other unbound providers. This wires the AI reader only: story activation, dialogs and other consumers remain with their owning story interfaces.

`Variable_Self.IsDifficulty` compares the requested enum with an AI-controlled seat's selected difficulty. Human and non-AI seats return numeric zero even if prepared content retains a difficulty name; an AI seat without the required parameter remains unavailable (WGA-424).

Fresh startup uses `CampaignServiceConfiguration::configure_native_ai`. Restore uses `GameLoadOptions::prepare_galactic`: each invocation returns fresh schedulers with registered bindings, the paired child factory/configurator, and a native installation closure retaining their exact parent host. Preparation happens before child reconstruction so parent-aware child Lua retains the same bindings on load. The checkpoint owner restores world, child, Lua and return state before calling the native closure, then restores the native contributors. The paired child setter refuses replacement while a tactical child is active. Preparation and installation neither service the AI nor reset saved deadlines (WGA-56/139, WGS-138/140).

Template trigger and explicit untrigger consumers initialize their equation output to zero and test whether it is positive; evaluation failure retains that local initial value (WGA-418/420). A failed trigger stays inactive, and a failed explicit untrigger retains the active template. Without an authored untrigger, the consumer negates the trigger test, so a failed or nonpositive trigger removes the template. The owning query still reports failure to Lua and proposal consumers under their separate rules; template handling does not publish a fabricated equation result.

The factory retains a real `Manager`, `GalacticWorld`, `Engine`, `GalacticFunding`, `LiveExecutionStateContributor` and `NativeActions`. Funding policy applies before initial ledger distribution. Native goal identity validation follows goal restoration; separate dead obligations remain retained. Native journal reconstruction runs with the AI frozen and replay-only handlers; the runtime action owner replaces those handlers at the completed boundary. Selection, billing observation and retained listeners use that runtime's shared owners (WGA-11..24/58..60/66, GFD-A01..08).

Funding equation consumers initialize their output from the category's current share, including zero for a fresh category, and retain that value when an authored equation fails. Maintenance sets categories without an equation to zero before clamping and normalization; a zero total distributes equal shares. Failed present equations, absent equations and successful zero remain distinct in the retained ledger. Query and Lua consumers still report evaluation failure (WGA-418/421/422). Startup evaluates policy before the ledger exists, so a missing ledger is the legitimate constructor-zero case. Maintenance runs only after initialization and refuses a missing ledger before evaluating weights; it cannot create a player ledger or replace its reservations. The difficulty reader requires `Parameter_Difficulty_Level_Type` and uses the sourced Easy/Normal/Hard enum values 0/1/2 (WGA-424); it accepts no `Parameter_Difficulty` alias.

The factory owns execution initialization and refresh. Initialization retains the current object-query nodes and authored movement limit, using the selected player's index among all players for the initial deadline. Refresh reads inputs only inside admitted execution when its saved deadline is due, orders the inputs by the retained nodes, and keeps the retained movement limit. Restored matrices rebuild through the real execution contributor without resetting the saved deadline. Complete derived route generations publish into perception without rebuilding its force or production copies (WGA-126..140).

The factory copies object-to-potential-plan reservations from the retained Engine, including pending absent actors, before and after admitted services and Lua commands. It updates the execution contributor through its validated mutator and publishes the same ownership into the Lua freestore pool. A fresh provider factory supplies independent mutable provider owners for startup, reconstruction and every native load. Full hash verification remains the oracle. This composition is not a mature performance measurement (WGA-56/139); revision-cache work remains tracked (legacy EAWR-2643).

## Required provider seams

The six service periods are session configuration in synchronization frames,
with GFC-A01..06 defaults 300/1/3/3/300/1. Lifecycle v2 saves the periods and
deadlines; a restore imports the saved periods rather than applying fresh
defaults. Periods must be positive and deadline addition remains checked.
Service order and the processing/auto-resolve gates remain GFS-A02/GFS-A16.

Production keeps an immutable world view with live motion deltas. Ownership,
visibility, roster, queue, credit, population and price-input changes invalidate
their consumed rows; a due saved perception deadline also refreshes the view.
GFS-A06 does not give all tokens a 300-frame lifetime: visibility notifications
remain immediate (GFS-A15), and site/admission readers remain conditional
(GFS-A10/GFS-A14). Producer prices are prepared in canonical player/planet
chunks, with a fixed simulation-frame slice across the perception period.
A reader can prepare its missing chunk immediately from the same immutable
inputs. Current admission and queue facts are evaluated for requested types,
without expanding every offer before each barrier. Prepared chunks and their
work cursors are derived caches; their readiness cannot change a result.

Per-tick galactic AI synchronization uses fingerprints of actual canonical
native state and cached Lua graph fingerprints with current scheduler metadata.
Lua execution, assignments and sandbox identity/memory changes invalidate the
graph cache; local cache epochs never enter a digest. Native restore invalidates
digest caches. Full native SHA and complete Lua saves remain checkpoint/oracle
operations, including the existing full-verification switch. The final galactic
AI state hash is 64 lowercase hex characters with the `ea470101` domain/version
prefix; it is a desync fingerprint. Checkpoint payload integrity remains SHA-256.

The usability producer derives `stealth_fleets` from the completed world's saved recursive combat-skip reader (WGM-163/169, WGA-185/360). A changed actor generation rebuilds this derived set once; idle requests reuse it. Fresh and restored connectivity bind it before selected-player presence queries. Unqualified actors or an unbound movement projection refuse. Strength, observer masks and the presence evaluator's retained cache deadline keep their existing owners. The derived set is not a second saved actor flag.

The usability archive v3 retains each player's consumed force expiry and pending work: input invalidation from the observer, access and relevant perception producers, separately from a pending site publication. Process-local generation numbers are rebased by reconstruction; the saved pending bits preserve the first ordinary service's decision. A whole-world fingerprint is not that decision: unrelated motion or queue clocks can change while the producer's inputs remain reusable. Reconstruction publishes the archived site lists without spending their deadlines or issuing ordinary ownership reads. The next admitted service consumes exactly the saved pending work or its independently due expiry (WGA-329, GFS-A14).

Startup refuses absent execution input/publication, action/Lua bindings, retained battle delivery, child parent context, original freestore traits, placement, or immediate work budgets. These refusals must be removed by qualified owning providers, not empty-success callbacks. Ordinary movement access and execution route costs remain distinct (WGA-126..140/228..240). Child context queries never service the frozen parent (WGA-80/81/202..207).

The stock provider factory reuses the native starting-force placement allocator, actual local/global conflict readers, and the Engine's saved movement identities. Its closures borrow the stable session implementation and parent world rather than a movable game facade. Each load binds the exact retained parent scheduler before listener notices. Generic stock Lua bindings use the same host's native action owner once; the child pair supplies its real parent equation evaluator.

Qualified external native contributors declare their component keys explicitly. Their payloads enter the same sorted native envelope and digest, with revision caches separate from the six core owner counters. They restore after perception, goals and funding, before execution consumers, and participate in the same forward rollback after refusal. A missing or colliding component identity refuses the composition. The usability provider uses `GALACTIC_USABILITY` for retained island and production-site cache state.

Each stock child equation closure binds the exact conflict's move-safe Timeline reader. The pending entry/restore binding completes at native installation; ordinary reads copy the current scalar by value, and a retired child retains its finalized slot rather than redirecting to the active galaxy or another child. The producer reads every canonical global player's stored current tech, including noncombatants, independently of tactical purchasing accounts (WGA-375..384/390..399). Nested parent equations keep the read-only cache and visibility boundary.

The gate runner records actual ownership changes, production events, conflict notices and tech progression. It writes real disk checkpoints at reservations, transit, a queued invasion and committed return, restores each on 1/2/4/8 workers, and compares every subsequent hash, event, account and persistent identity. Separate learning probes require the real first resumed completion and natural weighted choice. A game-time bound or synchronization guard cannot satisfy progression.

Observed digest requests time the retained compositor, then independently capture and recompute the full native hash outside that interval. Correctness processes keep full internal verification enabled; a separate Release benchmark process disables that internal oracle and still performs the independent full comparison after every request. Reports label the policy, actual changed/unchanged requests, mature goal/object sizes and core/external encoding counts. Internal-oracle timing cannot pass the production digest budget.

The installed case freezes the stock Equal Footing Underworld campaign with its authored Underworld human seat, seed 42, both Normal Empire/Rebel AI seats, no fog, 30 mode frames per second, a 900-second game-time budget and 4096 immediate instances/requests. Preparation independently verifies the missing-provider refusal. `--release` initializes the real stock root and runs the correctness gate with internal full verification; `--release-benchmark` repeats the same case with independently verified digest timing. Each writes its frozen identity, actual progression, disk and learning evidence, or an explicit startup refusal. Acceptance requires real builds, expansion, attacks, defence and tech progression, all four live save boundaries, subsequent learning/choice evidence, and qualified mature digest samples. These are executed release requirements, not claims inferred from source or supporting fixtures (legacy EAWR-1967, EAWR-1127).

The correctness gate also requires a naturally selected positive paid Empire proposal at its reservation checkpoint, a real unstaged Lua production task and exact build correlation. Post-return disk checks require an actual completed tactical child and evaluate the stock tech equation through the same query factory, with equal historical mode/tick/scalar/results and unchanged parent native bytes on 1/2/4/8 workers. These requirements do not claim an executed passing result.

The stock free-move input reader preserves WGA-400..404's no-source order: without a containing planet it reads no planetary permission, then native preflight refuses transit before containment success, route lookup, fleet launch or block creation. With a source it reads the qualified usability owner before the transit check. This ordinary native `false` does not increment the missing-reader counter; the campaign correctness gate still requires that counter to be zero and observes an actual free-fleet transit hop.

The qualified freestore publication derives stationary orbiting transport safety from the completed world's actual surface access, planet alliance, landed transport owners and authored ground capacity (WGA-30). It reuses the partitioned surface reduction used by the presence fixture. Raw retained facts, membership, reservations and archive bytes stay owned by QualifiedFreestore; the derived publication is cached until that owner's publication or the world's observer input generation changes. Missing surface/control input clears a previous derived answer and remains an explicit unavailable refusal in `Is_Unit_Safe`. Transit, nontransport and directly planet-parented actors retain the sourced safe bypass. Capacity counts nonnull, non-delete-pending landed entries, while the safety ownership reader still examines every nonnull landed entry (WGA-410).

Automatic ground-preference landing consumes this cached frontier during admitted due execution, after assignment and finished-movement cleanup and before Lua main/unit callbacks (WGA-405..416, GFS-A04/11). Suppressed auto-resolve planning does not enter it. Partitioned decisions read the native human/safety/transit/current-parent/preference/literal-grandparent/capacity/surface gates in that order, without cargo, original-type or reservation gates. Ordered commit rechecks capacity and surface access, directly removes the same transport from its current fleet and issues its fleetless land event. The event's formation-land notification follows even when the surface link fails; it does not prove containment or roll back the earlier removal. Derived staging buffers and count hints are reused, with hints incremented only by successful ordered links. The world owner recomputes its live landed count for both pre-removal admission and the link commit, asserting agreement with any supplied hint; the hint never authorizes capacity (WGA-416, ADR-009).

The actor's `UNIT_AI` presence comes from its loaded current behavior. Fresh actors initialize their retained preference true; `Set_Prefer_Ground_Over_Space` changes it through the native Lua transaction and returns no value. WGA-409 consumes the first Boolean argument and ignores additional Lua arguments; missing or invalid first arguments take the script-error route. This differs from the existing exact-arity `Prevent_AI_Usage` adapter. The immediate preference effect receives only the canonical actor/Boolean pair. Representation/location/owner changes retain the byte. NativeActions component codec 10 contains QualifiedFreestore codec 2, whose per-actor preference is exactly one canonical Boolean byte. Restore accepts only the new format and validates current behavior against the reconstructed actor owner. Stock hero destination selection remains independent. GAL-U01 still names the unobserved first arrival/return/load service, indirect preference propagation and mixed listener ties; this implementation does not infer those runtime facts. The direct world link owns surface containment and the formation notification; native story landing context/listener delivery and active-invasion-only link bypass remain named deployment seams, outside the automatic caller's strict capacity gate.

WGA-407/410 allow allied landed ownership through the sourced safety gate, while the current occupation owner retains WGM-C01's single landed owner. Until GAL-U01 settles the mixed-allied occupation policy (legacy EAWR-2815), ordered world admission exposes `mixed_allied_owner_unavailable` and skips before removal. This is a named deployment seam, not a sourced retail same-player gate. Direct attempts keep that world invariant and can still emit a failed-link formation notification. Delete-pending entries are excluded from both live capacity and the save validator's capacity bound; their ownership remains in the separate safety scan.

Economy aggregate memoization is scoped to one synchronized frame. Ordinary player aggregates still consume their observer-local ownership getters at each demand frame, including zero-interval observations (WGA-65/299). A warm live memo and a cold restored memo therefore publish identical native ownership and visibility timestamps without rebuilding unchanged physical economy inputs. This derived memo remains outside the archive and synchronization digest.

Perception capture sorts references to retained records under the owning cache lock instead of copying their strings and bindings. The WGA-195 canonical key order, ordered bindings, component domain/version and archive bytes remain unchanged.

Demand-time producer admission indexes immutable effective offers by original type identity. Requested types select their original registration positions, deduplicate repeated requests, and keep that order for first-allowed reads; unrequested offers are not tested. Queue durations, credits, population, blockers and reservation admission still come from the same owning snapshot (GFS-A14, WGA-329). The index and offer-check counter are derived work metadata and remain outside native archives and synchronization digests.

Producer admission demand reads memoize their complete owner/planet/type-set/first-allowed key for one completed input. Repeated or reordered equivalent requests reuse the same result, including errors; every publication gets a fresh memo, and retained earlier inputs retain their earlier source. This derived memo does not affect service order, native state, checkpoint bytes, or synchronization hashes.

Exact perception and visibility identities use derived ordered lookup indexes into the native record vectors. The complete context and ordered parameter bindings remain the cache key (WGA-62/65); expiry equality, hidden remembered reads, zero-interval reads, visibility refresh, and archive canonical order are unchanged. Restore and connectivity erasure invalidate lookup positions.

Qualified production-queue changes refresh source-owned producer admission, queue totals, checked queue clocks, and economy projections without rebuilding physical force/object rows. All nonqueue production fields, current technology, membership, ownership, observer inputs, publisher qualification and perception deadlines retain their existing invalidation checks (GFS-A14, WGA-329). Retained earlier inputs keep earlier queue values.

Current credit changes use the same source-owned admission/economy delta as queue progress. Copied account views and selection credits update at the completed frame; earlier inputs retain earlier credits. Credit caps, current/maximum technology and account identity retain full physical invalidation, including technology-dependent starting spawns.
