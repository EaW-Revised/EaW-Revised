# Land path budget and local movement

This is a static, read-only debug-build research note for the ground-combat
architecture programme. It supplies rules for L4 land search and L5 local
movement under the existing land movement work (legacy EAWR-1451). It changes no
simulation code. No retail capture or timing measurement was run.

Read the [land pathing walk](../../behaviour/walks/land-pathing.md) and
[frame service schedule](../../behaviour/frame-service-schedule.md) first:
FS-22, FC-44..46/67..69/71..72 and FD-64 establish shared formation boundaries.
Land service placement, first admission and reset cadence belong to the land
frame-map research, rather than being inferred from XML values here.

The original walk's open-item numbering matters: U-WLPA-1 owns quota and
collision clocks; U-WLPA-3 owns member steering and arrangement constants;
U-WLPA-6 owns contact subtype, mover choice and deadlock closure. The findings
below close specified subquestions, not those entire items.

Evidence groups ER3-A (quota/search), ER3-B (contacts/deadlock) and ER3-C
(member movement), plus ER3-D (coordinate conversion), are fresh debug-build
inspections. Query receipts, binary identifiers and raw output remain private under ignored
`out/research/gc-land-r3/`. Existing WLPA rules are cited separately. A
symbol-name match alone is not behavioral evidence.

## Implementation consequences

The shared BF-4 service can host deterministic land slices, but it needs separate
states for admission denied, search in progress, path failure, path installation
and actual movement start. Graph-node quota accounting is not a substitute for
a deterministic graph-building/expansion work budget. A completed search must
retain its contact and order identity through ordered commit; the existing
space slice size or landing delay is not a sourced land default.

L4 owns static terrain/width admission and search state. L5 owns dynamic
temporary routes, contact state, speed roles and their invalidation. The grid
and occupancy inputs come from L1; member identity comes from L2. L6 can show
the resulting movement, but presentation poses are not proof of path admission.
Use immutable partition inputs, disjoint proposals and ordered commits, equal
on 1/2/4/8 workers. Those are remake design decisions, not a claim that retail
uses this threading model.
