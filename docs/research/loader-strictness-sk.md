# SK loader strictness inventory ((legacy EAWR-4994), SK share)

Scope: units / combat / movement / fighter / presentation numeric validators in the loaders. Source: our loaders on main (80890b8e3; part 2 re-read on origin/main at its tip). Retail rule: the FoC debug build parse rules recorded in the GC inventory (out/strictness/gc-inventory.md, walked on the shared database-map reader) plus the registry `value_type` in docs/tag-coverage/engine-tags.json. Inventory and classification only: no mod sweep, no fixes, no new Ghidra walks (burn tasks, parts 1 and 2).

## Retail parse rules (from the GC walk; assumed for object-definition and ability tables)

| Parser type | Retail behaviour |
|---|---|
| signed integer | `atoi`: optional sign, leading digits, fraction truncates toward zero, text -> 0, no range or sign check |
| unsigned integer | same `atoi`, reinterpreted unsigned: a negative wraps to a huge value |
| float | `atof`, no range or sign check |
| unit float | `atof`, warning and clamp to [0, 1] |
| any | empty value skipped (constructor default); unknown tag = warning |

Open assumption: dispatch for object-definition and ability tables shares the reader the GC worker walked; one spot-check walk per table kind is a follow-up.

## Top 5 STRICTER (expected mod impact; no mod sweep done)

1. **MaxWaypointsPerPath** (SKI-27, movement): negative fails the whole motion table; AaW authors -1 (legacy EAWR-4992); retail wraps to unbounded.
2. **Text or fractions in numeric tags** (SKI-01, SKI-02): retail reads text as 0 and truncates fractions; we drop the value or fail the type.
3. **whole() users: recharge / delay seconds** (SKI-08, combat): a negative or huge value fails the type; mods use negative sentinels (cf. RaW ion-stun, (legacy EAWR-4589)).
4. **Stacking_Category** (SKI-22, combat): a negative category is dropped to the default, merging distinct stacking keys (same as GC LSA-24).
5. **Stealth_Detection_Time / Manual cooldown / planetary timings, [0,3600] s caps** (SKI-24, SKI-09, SKI-10): hard failure for values retail accepts.

## Per-family fix plan (est PRs)

Estimates are gut-level from STRICTER row counts, not measured PRs; the GC share's F1/F2/F3 families are the template.

- **F1 integer truncation (all families)**: one `retail_int()` helper that truncates and maps text to 0, used by SKI-01, 02, 04, 06, 19, 21, 34, 36, 39, 40, 42, 43 and (part 2) the presentation readers SKI-49, 50, 54, 59, 60, 63. 1 PR for the units helper; 1 more for a shared presentation `retail_number()` (prefix parse, text -> 0) covering SKI-47, 51, 53, 56, 57, 61, 62.
- **F2 unsigned wrap**: Fire_Pulse_Count, Tech_Level, Base_Level, MaxWaypointsPerPath, SpacePathing*; consumer walks first, except MaxWaypointsPerPath, a one-line first PR that unblocks AaW. It must also relax the sim check in SKI-67 (waypoints <= 65536).
- **F3 float sign / caps (combat)**: whole() users, manual cooldown, planetary timings, Charge_Up, Stealth_Transition, Stealth_Detection_Time; 1 PR after a timer-consumer walk.
- **F4 stacking categories**: 1 small PR, shared with GC LSA-24.
- **F5 movement constants**: MovementReevaluationFrameCount, Space_Guard_Range, SpaceObjectTracking*, and the avoidance-rule range checks (SKI-32, 67): 1 PR with the MaxWaypoints fix. Loader and validator must change together.
- **F6 fighter squads**: spawn pair counts, land-company Max_Squad_Size, FormationMin/MaxSideError (SKI-68): 1 small PR.
- **F7 sim validator caps (new, part 2)**: SKI-33, 64-66, 69-73. Decide per cap: keep as a documented sim limit that reports and clamps (preferred, so a mod keeps loading) or drop it; no retail walk needed for the pure range caps, but zero/negative consumer meaning (rocket curve distance, laser radius) needs one. 2 PRs: durability/damage (SKI-33, 64-66) and ability/rocket/economy (SKI-69-73).
