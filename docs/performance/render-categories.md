# Presentation category diagnostics

Pass `--eawr-render-counters` to enable presentation-only accounting. It does not change simulation state, replay bytes, camera, visibility, materials or rendering. The default path does not enumerate diagnostic sources. No GPU draw reduction is implemented.

After each drawn frame, the sampler records actual root viewport visible, shadow and canvas draw calls beside producer-role counts. Sources are filtered by their owning viewport RID: sub-viewport renderers and particle backends are excluded from a root-viewport sample. The log includes that viewport ID; the counts do not aggregate every renderer in the process. Canvas is the UI draw scope. The overlay shows `V/S/UI` for those draw counts and `S/R/C` for submitted instances, retained instances and eligible shadow casters. The CSV appends named columns; the log emits `EAWR_RENDER_CATEGORIES` JSON every 60 engine frames, and the overlay report includes the same object.

Roles describe provenance: hull/unit surfaces, attached hardpoint/turret art, effect shells, particle emitter meshes, primary/secondary sky, other environment/map surfaces and unknown. An integrated turret animated within a hull surface remains hull geometry; it is not a separate attached hardpoint draw. Uninstrumented producers remain unknown. Shared uploads do not determine the role of an instance. Fog copies retain their source provenance.

Submitted means a retained renderer instance appeared in a submission during the sampled engine frame, or a particle emitter received an update. Repeated submissions/reads within that frame count an instance once. Retained includes hidden or off-camera geometry still owned by that backend; an eligible caster is permitted by its instance opacity and shadow policy, whether or not the light, frustum or cascades draw it. Particle meshes never cast shadows. Retained surfaces count uploaded mesh surfaces, not triangles or actual visible draws. Particle meshes parked in the reuse cache are excluded from active backend-instance counts.

Role subtotals partition the instrumented instances. Shadow eligibility overlaps the roles and must not be added to them. These counters cannot establish draw calls per hardpoint, GPU time per category, render-state changes or the engine's instancing ratio. Use a GPU command capture for those claims. The viewport counts describe the completed engine draw; a CSV row consumes the latest completed sample and carries its engine frame number separately from the current viewer trace frame.

`render_counter_ms` measures the sampler traversal plus viewport queries, excluding throttled JSON formatting and log I/O. Measure OFF/ON whole-frame controls as well before judging overhead; the counter value alone omits opt-in per-submit bookkeeping and logging. The focused contract prints an independently timed warmed traversal of 10,000 diagnostic records as a CPU scale check, not a GPU saving or a frame-time prediction.

Diagnostic sources register without allocation, unregister on destruction, and are read on the same viewer submission thread as the rendering APIs they observe. Frame-local submissions reset by engine frame ID; retention follows actual renderer/backend ownership. No authoritative simulation fields or replay hashes are involved, so headless replay comparison is not a validation gate for this presentation-only change.


## Draw-type producer accounting and ablation

Diagnostic flag registry (presentation only; no new XML tag or catalog consumer):

| Flag | Values | Application target |
|---|---|---|
| `--eawr-drawtype-ablate` | `none`, `hull`, `hardpoint`, `effect`, `particle`, `debris`, `wreck`, `shadows` | `ViewerHost::_ready`, `render_categories::engine_visible`, `render_categories::engine_casts` |
| Benchmark `--drawtype-ablate` | `all` or one viewer ablation value | `tools/performance/remake_bench.py::write_spec` |
| `--eawr-drawtype-ablate` distance experiments | `hardpoint-band-005/010/020`, `particle-band-005/010/020`, `shadows-band-005/010/020` (each suffix is a separate value) | `render_categories::band_cutoff`, `distance_band::coverage`, renderer/particle submission |
| `--eawr-drawtype-ablate groups` | hide all but one compatible retained unit | `GodotRenderer::Impl::update_diagnostic_instances` |
| `--eawr-drawtype-ablate` hull split | `integrated-turret`, `other-hull` | upstream `hull_part` attribution, renderer diagnostic submission |
| Benchmark `--drawtype-ablate bands` | matched `none`, nine distance bands, `groups`, and both hull split ablations | `tools/performance/remake_bench.py::write_spec` |

Distance experiments use projected bounding diameter / viewport height below 0.5%, 1% or 2%, with a 10% larger exit threshold. Bounds crossing the near plane, missing cameras and invalid/empty bounds remain visible. Mesh bounds conservatively union used skin palette transforms and all surfaces of the owning composed unit; hardpoints with unknown owners remain visible. This prevents a tiny surface on a nearby capital ship entering a distant-object band. Standalone shadow casters use their resource bounds; emitter bounds use current live geometry. These flags suppress diagnostic submissions only; simulation, authored visibility and particle stepping stay authoritative. The shadow experiment changes casting separately from colour visibility. No distance treatment is enabled by default.

All ablation controls count retained/eligible identical-unit candidates on the producer side. Composition carries unit ownership and model path; compatibility requires the same surface asset identities (including materials/shaders), full pose palette, visibility, tint, light scale, opacity, caster state and category. Camera-facing billboard assets are excluded. Per-unit world transforms may differ. Candidates span the scene: squadron membership is not exposed here. Counts include off-camera units and estimate colour surface incidence only; they do not establish final visible draws, shadow passes or actual instancing performance. `groups` hides the duplicate units for a measured cost bound and never creates an instanced draw.

The model upload carries opt-in original mesh-name tags into each retained surface record. Names alone do not establish integrated turret ownership. Composition also carries a diagnostic surface part from XML-resolved `Turret_Bone_Name` and `Barrel_Bone_Name`, including inline hardpoints (HPT-07). Rigid descendants and skin influences wholly within declared turret subtrees become `declared_turret_surfaces`; surfaces outside those roots become `other_hull_surfaces`. Missing or unresolved roots, mixed turret/body skinning and malformed ancestry remain `unclassified_hull_surfaces`. These are retained surface incidences, not visible draw counts; the paired split ablations independently measure viewport draw and render-CPU deltas. Hardpoint bands include these declared integrated turret surfaces as well as the separately composed hardpoint role. Undeclared/static turret art cannot be distinguished from other hull by this diagnostic. No XML extension is introduced by these command-line diagnostics.
| Benchmark `--drawtype-repeats` | integer >= 2 | `tools/performance/remake_bench.py::write_spec` |
| Driver `drawtypeResources` | boolean | `tools/rig/drivers/perf-sample.ps1` resource sampler |
| Report `--out` | output directory | `tools/performance/drawtype_profile.py::write_outputs` |

The flag enables render counters. `none` is the instrumented control. Values are startup-only; unsupported or missing values exit with status 2. Production viewer flag-off native CSV columns and diagnostic JSON schema remain unchanged; the benchmark observer/results add primitives as requested. No diagnostic traversal or triangle accounting runs with counters/diagnostics disabled. No simulation or replay field changes.

Requested visibility remains independent of applied RenderingServer visibility. Retained proxy activation/deactivation, ordinary instance visibility changes and particle submission caches apply suppression after the requested state. Resource retention, transforms and particle simulation continue. Producer counts and caster eligibility describe requested state before diagnostic suppression. Hull includes integrated turrets; hardpoint means separately composed attached art. Shadows means the instrumented GodotRenderer casters only, retaining opacity and noncasting policy; it is not a claim that every possible engine shadow producer is suppressed. Projectile, terrain/environment, HUD/selection and other are **not separable** in this diagnostic. Unit class is unknown: no additional catalog traversal is added to the battle path.

Opt-in JSON adds uploaded triangle incidence, surface material incidence (not unique materials or state switches), and eligible single-shadow-pass surface incidence. Particle triangle incidence is allocated topology capacity, including degenerate unused tail slots. Counts include retained hidden/off-camera resources. The draw estimate is one colour pass plus one eligible shadow pass per retained surface; it does not measure engine-internal passes, cascades, culling, batching, or per-type GPU/CPU submission time.

Run `tools/performance/remake_bench.py run ... --drawtype-ablate all --drawtype-repeats 3` for matched controls and ablations. Repeated category order rotates to reduce drift; every process uses the same timing-query instrumentation and Separate render mode. The bench includes primitives in results. Run `tools/performance/drawtype_profile.py <results.json> [<results.json> ...] --out <directory>` for JSON, a table and a standalone SVG heatmap. Inputs must share host, exact viewer/DLL and engine build, and uncapped pacing; every measured category needs all paired control repeats. All-zero paired GPU timers stay unavailable. Nonseparable map/sky and unknown producers retain their available geometry accounting. Table draw share is **draw delta / control total**, not additive category attribution. Report median and min/max across paired repeats; negative deltas remain visible. CPU/GPU deltas are conditional on the timing-query synchronization overhead. Live producer samples join the native tick window through completed `render_counter_frame` IDs; other sources remain process-scoped and labelled. The native samples also prove the selected ablation. Producer min/max spans sampled frames, while timing-delta min/max spans paired run medians. Never sum ablation deltas or call them per-draw costs.

Diagnostic bench runs also enable `drawtypeResources` on the process sampler: buffered per-core CPU busy and NVIDIA GPU busy samples join the existing per-thread CPU/wait-reason sidecars. GPU queries run in hidden child processes with a one-second bound; missing counters stay unavailable. These machine-wide samples cover the process lifetime, including startup, rather than the combat window. Their cost is present in every matched control. The heatmap labels measured draw/CPU deltas separately from estimated producer draw share.

The bench snapshots the engine pins enforced by the rig controller before launching each job, retaining `engine-pins.json` beside its results. Exported figures include the exact GUI engine SHA-256 and the observed engine banner; analysis does not infer the engine from the current installation. A failed invocation cannot reuse an old run directory as its receipt.

Exports retain a RED diagnostic label when a measured run logs engine errors; no speedup claim is inferred from those figures.

For free-pacing runs the benchmark stages an isolated settings file with `video.vsync=0` and `video.frame_rate_limit=0`, and explicitly disables live audio pacing. This keeps launch-profile and battle settings independent of player files and capped defaults. Post-draw observer samples and native tick traces must demonstrate max_fps=0 and vsync=0. Producer shadow-pass incidence overlaps role estimates; the shadow row estimates only eligible single-pass surfaces, with triangles/materials unavailable. Measured draw-share and producer-estimated share leaders are named separately.

## Instanced hull submission (default on, `--eawr-no-instanced-hulls` turns it off)

Pieces of one asset that are opaque, not camera-facing, in their bind pose (every influencing bone at identity), visible, and equal in caster state, tint and light scale draw through one multimesh per group instead of one mesh instance each. A group opens at two matured pieces; a piece matures after two submits with the same eligible state, leaves at once when its state changes, and a piece that left because its pose moved stays single for 90 submits. The retained per-entity instance stays (hidden while batched, resynced when it leaves), so every per-entity path is unchanged. Batching is on by default. The launch argument `--eawr-no-instanced-hulls` turns it off for bisecting a suspect case and for OFF-versus-ON measurements (with it nothing is created and no hook runs work); the startup log line `EAWR instanced hulls: on|off` states the actual state. The old `--eawr-instanced-hulls` argument is ignored. Tests also switch `hull_batching::enabled` directly. A multimesh is culled as one object by a box around its members, so off-screen members still run the vertex stage; skinned non-rest pieces, billboards, alpha passes, proxies and any ablation other than `none` are never batched. Presentation only: no simulation state is read or written. `--eawr-render-counters` (or `--eawr-drawtype-ablate none`) adds a `batching` object (groups, members, collapsed surfaces, joins, leaves, flushes, repairs) to the counter line; the `rest_pose_batching` diagnostic estimates the yield.
